# 唤醒判据：裁决材料

> 无产品权威。本文把裁决需要的事实摆齐，并列出几个互斥选项和各自的后果。
> 选项不是产品判断，判断在维护者。相关讨论见
> [后台 job 讨论记录](./background-job-design-notes.md) §6。

---

## 1. 要决定什么

**模型空闲时，哪些后端事件应该开一轮？**

这条判据现在**不存在**。它之所以现在要定，是因为「事件可以在模型空闲时推送」
等价于「空闲时唤醒」——推送本身就是开一轮。

注意它与另一条判据**正交**：

| | 判据 | 状态 |
|---|---|---|
| 算不算**事件**（进帧） | 「状态里不留痕 ∧ 在场玩家会感知到」 | 已定 |
| 要不要**唤醒**（空闲时开一轮） | —— | **没有** |

**是事件 ≠ 该唤醒。** 没点名的聊天是事件（在场玩家听得见），但不该把同伴叫起来。

---

## 2. 今天唯一的唤醒源

`evaluate_backend_wake`（`participant/runtime/mod.rs:996-1017`）逐条：

| 输入 | 结果 |
|---|---|
| 终止生命周期（Faulted / Stopped） | **不唤醒**（`:1002-1004`，另走 `stop_cleanup`） |
| 不是 chat | **不唤醒**（`:1005-1007`） |
| 是 chat 但解析不出玩家消息 | **不唤醒**（`:1009-1011`） |
| 是 chat 且 `addresses_player_chat` | **唤醒**（`:1012-1013`） |

**全系统只有一个唤醒源：被点名的玩家聊天。**

---

## 3. ⚠ 一条会改变选项形状的结构耦合

`mod.rs:438-439`：

```rust
let pending_fact =
    (!terminal && record_fact && wake_candidate.is_none()).then(|| ParticipantFact { ... });
```

**唤醒的事件不会成为事实。** 二者今天是互斥的：被点名的聊天作为这一轮的
`trigger` 送进去，不再作为 pending fact 进帧。

后果：**放开唤醒集，等于把那批事件从事实通道里拿走。**

所以裁决实际上要回答两个问题，第二个容易被漏掉：

1. 哪些事件唤醒？
2. **被唤醒的事件还进不进帧？**
   - 保持互斥 → 「疼」唤醒之后，疼本身不在帧里，模型得自己去 `status.health` 查
   - 要兼得 → 得改 `:439` 这一行，让 wake 的事件同时落 fact

## 4. 候选集是封闭的

后端事件一共 9 个产品类 + 1 个非产品类（`contracts/minecraft/event.rs:24-36`）。
「是否事实」按 `backend_event_is_fact`（`support.rs:258`）：

| 事件类 | 今天是事实 | 今天唤醒 | 流量量级 | 玩家能否感知 |
|---|---|---|---|---|
| `Lifecycle` | 是 | 否 | 极低 | 部分（掉线） |
| `Chat` | 是 | **仅被点名时** | 低 | 是 |
| `World` | 是 | 否 | 低 | 是（换维度等） |
| `PlayerList` | 进出算，`Update` 不算 | 否 | 低 | 进出算 |
| `SelfState` | **否** | 否 | 极低 | —— 目前只有 `ServerPositionCorrection` |
| `Entity` | 否 | 否 | **最大** | 是（视口的活，A06/W08c） |
| `Block` | 否 | 否 | **大** | 是（视口的活） |
| `Sound` | 否 | 否 | 中 | 是（已在 `sound.recentSounds`） |
| `SnapshotChanged` | 否 | 否 | 高 | 否（内部记账） |
| `Overflow` | 条件 | 否 | 低 | 否 |

### 4.1 ⚠ 「疼」这个候选**现在还不存在**

- `ProtocolEntityEvent::Hurt`（`event.rs:261`）存在，
  但实体事件**明确排除自己**：`is_admitted_non_local_entity(local, target) = local != target`
  （`producers.rs:367`）。它是「**别人**被打了」。
- `ProtocolSelfEvent`（`event.rs:366`）**只有一个变体**
  `ServerPositionCorrection`，不带血量。
- 自身伤害目前只以 `status.health` 存在——**状态**，扣血本身不留痕。

**所以凡是含「疼」的选项都带一个前置**：先补自身受伤事件。补的时候两颗雷：

1. **别走 `Entity`**——那条路已被排除自己；自身受伤应走 `SelfState` 或新变体。
2. **`SelfState` 现在在 `backend_event_is_fact` 里是 `false`**，届时要一起改。
   `support.rs:254-255` 给的理由是「目前只有 `ServerPositionCorrection`」——
   这个理由**自身受伤一进来就不成立**。若有人按它把 `SelfState` 整个挡掉，
   应写成**按变体判**而非按 payload 类型判。

## 5. 三条约束

### 5.1 预算：每次唤醒至少烧一个模型请求

`toolloop/src/run.rs:10-12`：

```rust
pub const MAX_MODEL_REQUESTS_PER_RUN: usize = 16;
pub const MAX_TOOL_CALLS_PER_RESPONSE: usize = 8;
pub const MAX_TOOL_CALLS_PER_RUN: usize = 32;
```

一次唤醒 = 至少一轮 = 至少一次模型请求。繁忙世界里判据一宽，
同伴会被叫起来到停不下来。

> 更正：我此前在别处写过「180 秒期限」，`toolloop` 里**没有**这个常量。
> 不要沿用那句话。

### 5.2 自激

同伴自己走路 → 产生事件 → 唤醒自己 → 再走 → 再唤醒。

判据里必须有「自己造成的不算」。现成的挡法是事实来源标签
（`event.rs:16-20`）：

```rust
pub enum FactSource { Commanded, ClientPredicted, ServerObserved }
```

`Commanded` / `ClientPredicted` 是同伴自己动作的产物，天然该排除。

### 5.3 与 Q08 的关系

「没人说话时同伴活不活动」（Q08）和「疼了能不能出声」是**两个问题**。
把唤醒判据起得窄，Q08 可以继续挂着不决。判据一旦放宽到「世界有动静就醒」，
Q08 就被这条判据代答了。

## 6. 三个选项

### 选项 A · 窄：疼 + 被点名

唤醒集 = {自身受伤/死亡, 被点名的聊天}，其余一概只进帧。

- **前置**：先补自身受伤事件（§4.1）
- **效果**：「走进岩浆」有人管；「隔壁有人挖矿」不吵它
- **预算**：几乎不增加唤醒频率
- **自激**：天然免疫——挨打是 `ServerObserved`，不是自己造成的
- **留开**：Q08 继续挂着；以后放宽是**加条目不是改结构**
- **代价**：世界里发生的绝大多数事，同伴要等下次被叫醒才知道

### 选项 B · 中：疼 + 被点名 + 在场变化

在 A 之上加 {玩家进出世界, 换维度}（即 `PlayerList` 进出 + `World`）。

- **效果**：有人来了同伴会主动打招呼
- **预算**：多人服务器上进出频繁，唤醒次数明显上升
- **自激**：仍免疫（都不是自己造成的）
- **风险**：「有人进服 = 该说话」是一条产品判断，不是技术判断——
  它等于替 Q08 答了一半

### 选项 C · 宽：所有 `ServerObserved` 的事实

唤醒集 = 所有 `FactSource::ServerObserved` 且 `backend_event_is_fact` 的事件。

- **效果**：同伴对世界最灵敏
- **预算**：**最危险的一个**。繁忙服务器上聊天流水本身就能把预算打光
- **自激**：靠 `ServerObserved` 挡住了自己的动作，但**挡不住别人对自己动作的反应**
- **判据本身很干净**（一行谓词），但后果最难预测

---

## 7. 我的建议（⚠ 只是建议，不是判断）

**选 A，并且让唤醒的事件同时进帧**（即改 `mod.rs:439` 那一行）。

理由三条：

1. **窄判据的错误是可恢复的，宽判据的不是。** 起窄了，症状是「同伴对某件事没反应」，
   看得见、加条目就能修。起宽了，症状是「同伴一直在说话、预算烧光、不知道为什么」，
   而且要往回收就得改结构。
2. **A 是唯一不替 Q08 作答的选项。** B 和 C 都隐含了「同伴该主动社交/主动反应」，
   那是产品判断，应该单独决定。
3. **让唤醒事件同时进帧**，是因为把「疼」做成纯 trigger 而不进帧，
   等于要求模型自己回想刚才发生了什么。W07a 的方向是不把未知说成已知，
   同理不该把已知藏起来。

## 8. 定了之后要改哪几处

| 选项 | 要动的地方 |
|---|---|
| 任何含「疼」的 | 新增自身受伤事件：`ProtocolSelfEvent` 加变体 + 后端产生方；`backend_event_is_fact` 的 `SelfState` 分支改按变体判 |
| 任何放宽的 | `evaluate_backend_wake`（`mod.rs:996-1017`）——现在是硬编码的 chat 分支，要改成谓词 |
| 「唤醒也进帧」 | `mod.rs:439` 去掉 `wake_candidate.is_none()` 条件；要同时确认 trigger 与 fact 不会让模型看到重复的同一件事 |
| 任何选项 | 自激防护：谓词里排除 `Commanded` / `ClientPredicted` |
