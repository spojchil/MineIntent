# 寻路器设想

> **定位**：本文件描述寻路器的**目标设计（设想）**，不是当前实现。当前实现见 [`architecture.md`](./architecture.md)。本文件无产品权威；产品判断见 [`产品.md`](./产品.md)。未决项以「待定 / 搁置」标注，最终裁决以产品文档与维护者确认为准。

## 0. 一句话

寻路器把三种**结果目标**（去 / 挖 / 放）在**模型自管的方块策略**约束下，执行成「世界状态到达目标」；方法（走 / 挖 / 垫 / 搭）由机器内部决定，不暴露给模型。

## 1. 原则

1. **模型自管**：方块策略是模型自己的状态（与长期记忆同性质），自由创建/修改，无需理由、无强制审计。理由：AI 是否保护某处、是否愿意破坏某物，是它自己的选择（R01、A05），不是运行时替它定的。
2. **运行时忠实执行**：机器照策略执行，不评判、不要求解释；世界物理由 W03（按实际结果判成败）兜底。基岩挖不动、空气能走——这些是世界事实，运行时不必、也不该替模型在策略上再加一道判断。
3. **白名单 / 默认拒绝**：没明说允许 = 不允许。注意（W06）：这只是**求值层缺省**，模型写通配规则可覆盖；运行时**不保留模型不可改的硬底槽**，唯一硬底是世界物理。
4. **目标 = 结果，方法 = 内部**：意图表达结果，走/挖/垫是机器内部手段，由策略门控。模型不编排「走→挖墙→再走」这种半成品步骤。
5. **严格契约**：参数与列约定严格校验，多给 = 拒绝并说明（W07a），不静默忽略。

## 2. 方块清单（BlockPolicy）

### 2.1 SQL 宇宙里的三张表

| 表 | 是什么 | 例子 |
|---|---|---|
| `seen_blocks` / `seen_empty` | **世界**（实例，观察所得） | 「我见过的铁矿在哪」 |
| `all_blocks` | **类型总表**（全部 BlockKind，含工具需求、硬度等事实） | 「钻石矿需要镐才有掉落」 |
| `block_policy` | **策略**（规则，模型自管） | 「哪些方块/区域可挖」 |

清单是 SQL 面里的**第三张表**，复用 `sql::run` 整条链路（连接装配、300ms 预算、授权器、渲染），与 `me` 表同款 `materialize()` 模式。

### 2.2 规则 = 布尔谓词（DNF）

- 叶子：`name MATCHES <glob>`、`pos IN <AABB>`（`op` 由入口决定，不进叶子，避免冗余）。
- 组合：`AND / OR / NOT / 括号`。
- 两维独立可选：`name` 与 `region` 各自可缺省（缺 = 通配）。`deny break IN [房子]` 是**空间保护**，与方块类型无关——「保护空间」和「保护类型」是两个正交维度。
- **布尔谓词消灭「优先级」问题**：谓词本身即完整答案，无顺序、无 specificity、无「谁覆盖谁」。

### 2.3 命名 DNF + 组合

模型可保存多份命名 DNF 并互相 `REF`（组合细节不具体设计，v1 可平铺）：

```
nav_break     = *_ore OR *_log OR dirt OR gravel
mine_break    = *_ore OR deepslate_* OR copper_ore
place         = cobblestone OR dirt
protect_house = IN [房子]
break_nav     = nav_break AND NOT protect_house
```

机器查询的**固定入口**：`break_nav` / `break_mine` / `place` / `use_on`。入口背后怎么组合由模型自定。

### 2.4 双速消费

| 消费者 | 何时 | 用 |
|---|---|---|
| 机器（寻路代价、挖掘/放置门控） | 每 tick / 每格 | 求值布尔谓词（glob + AABB，快） |
| 模型（推理） | 偶尔 | 完整 SQL（`blocks` 工具，JOIN 三张表） |

清单**读走 SQL（只读）**，**写走 `policy` 工具**（定向编辑命名 DNF）——SQL 面只读保证不松动。

### 2.5 白名单语义

默认 deny（谓词求值为假 = 拒绝）；「保护」= 缺省或显式 `deny`；世界物理 W03 兜底；无运行时保留槽。

## 3. 目标层（Goal）

### 3.1 本质：谓词概念，枚举实现

目标是「让世界满足谓词」（`at(X)` / `empty(P)` / `filled(P,B)`），但机器端收**结构化枚举值**（具体坐标），不是自由 DNF——「逐格判定谓词」机器能干，「规划以满足谓词」需要通用规划器，是另一回事。具体化（哪几块）由模型用 SQL 完成，机器只执行枚举。

### 3.2 三种模式（完整能力，策略作限制）

```
Navigate(X)  → 结果：身体在 X
Mine([...])  → 结果：这些坐标现在是空气
Build([...]) → 结果：这些坐标现在是目标方块
```

内部走/挖/垫/搭**都允许**，但**是否挖/放由模型的 `break_nav` / `place` DNF 决定**——策略是限制器，不设 v1 子集。

### 3.3 参数（严格契约）

```
Navigate：单个坐标 [x, y, z]
Mine：    坐标数组 [[x,y,z], …]       SQL 必须恰好返回 x,y,z 三列
Build：   (坐标,方块) 数组 [[x,y,z,block], …]   SQL 必须恰好四列
```

**SQL 是语法糖**：工具层 `run_structured` 跑一次 → 冻结成三元组 → 机器只收坐标。`me` 在受理时刻自动冻结。0 行报「无匹配」；超时/报错原样透传。

### 3.4 两种写法并存

- **SQL** = 从已观察里选一批（「挖我见过的所有铁矿」）；**手写坐标** = 指向任意已知点（航点 / 玩家给的 / 记忆），是越过雾边界的逃生口。
- **不接受「SQL 当动态目标」**：机器持有查询反复跑会拖进雾边界 / 动态终局 / 变量冻结三件事；「探索 + 重查 + 再挖」是模型的回合循环，不是机器持有的查询。

### 3.5 意图层 vs 管理层

| 层 | 工具 | 回答什么 |
|---|---|---|
| 意图层 | `goal`（navigate / mine / build，无 cancel） | 我想要什么结果 |
| 管理层 | `jobs`（list + cancel） | 现在跑着什么 / 取消它 |

取消是 job 生命周期，不是 goal 模式。

### 3.6 一个槽、不替换、显式取消

槽里有 job 再发 `goal` → 拒绝「先 cancel」；无目标 `cancel` = 空操作成功。放弃必须是模型显式说出口的 `cancel`（W07a），不静默顶替。

### 3.7 模型面收敛：原语 + 目标

原语（`attack` / `use_on` / `use_item` / `look` / `move` / `jump` / `sneak` / `sprint` / `select_slot` / `swap` / `drop`）+ 目标（`goal`）。`hand.mine` / `hand.place` 吸收进 goal；`place_block` 先降级为内部积木，后并进 movement。左键双重身份：打实体（`attack`，留原语）vs 破坏方块（`mine`，吸收）；右键同理：交互（`use_on`）vs 放置（`build`）。

## 4. 机器执行分层

三层复杂度天差地别：

| 层 | 做什么 | 复杂度 | 现状 |
|---|---|---|---|
| **决策** | 挖哪块 / 放哪块（绕 vs 挖 vs 搭） | 难 | 未决（§5） |
| **导航** | 靠近目标（reach + 朝向/站位） | 难 | 已基本完成（雾导航） |
| **动作** | 对相邻方块转头 + 左键/右键 | 简单 | 已完成（`begin_mining` / `place_block`） |

- **复用 + 加判断**：策略 DNF 求值插在现有判断处——fork 文件 `world.rs`（规划代价，`break_nav`）、`moves/mod.rs`（执行，`break_mine`）；MineIntent `mining.rs` / `door.rs`（显式挖放，`break_mine` / `place`）。fork 可碰。
- **自动工具**：机器机械自动选最佳工具（`best_tool_in_hotbar_for_block`），不是策略维度；「需要什么工具」是 `all_blocks` 的事实。
- **策略拒绝必须报告原因（W07）**：拒绝时报告「哪个入口、哪条规则」，不静默。

## 5. 决策层（寻路一体化）

### 5.1 mine / build 统一 = 替换世界方块

```
mine  = replace(P, 当前方块, air)
build = replace(P, air, 目标方块)
```

**判据 = 世界状态谓词**：`world[P] == 目标`（mine→空气，build→方块），符合 W03（可验证）。

**「要空气还是要获取」：取空气。** 「获取掉落」是替换成空气的**世界后果**，不是 goal 判据；它是模型的**上游决策**（用 `all_blocks` 的工具需求/硬度判断「值不值得挖」）。没工具时「make air」仍成功（慢、无掉落），终局如实报告——把「清掉」和「拿到东西」两件事分开，判据只认前者。

### 5.2 参考 Baritone（三层抄法）

- **任务层**抄 GOAP/DEPS 声明模型（目标 = 世界状态谓词）——即 §3。
- **路径层**抄 Baritone：Movement 带副作用声明 + tick 代价标尺 + 分片规划。
- **执行层**抄 Baritone：授权格（只挖规划期计入代价的方块）+ 重算取消五件套。

**不抄**：Baritone 默认在真实世界规划（与观察记忆哲学相反，只抄其 BlockSource 抽象）；`hasThrowaway` 全局布尔（学 mineflayer 的剩余垫块计数）；`prepared()` 暴力兜底挖；GOAP 纯状态空间搜索；mineflayer 盲执行。

**前提**：启用挖掘后，未知哨兵（Fire）必须不可挖，否则 A* 会免费挖穿未见格。

## 6. 否定过的方向（为什么长这样）

### 策略层

| 否定 | 理由 |
|---|---|
| 维护者种子分类（自然/人工） | 清单应是模型自己的状态，不是运行时常量 |
| 强制理由 / 审计 | W09 约束产品决定，不约束 AI 每次选择（待确认） |
| 黑名单（默认允许） | 破坏不可逆，「宁可误伤、不可漏放」 |
| 顺序优先级（.gitignore）/ specificity | 类型与区域正交，布尔谓词直接消灭优先级 |
| 运行时保留硬底槽 | W06 不加限制，唯一硬底是世界物理 |
| letta label 结构化 / mem0 向量 | 违反 M07（无结构记忆）/ 需 embedding 基建 |

### 目标层

| 否定 | 理由 |
|---|---|
| SQL 当动态目标（机器持有查询） | 雾边界 / 动态终局 / 变量冻结三件事 |
| 自由 DNF 当目标 | 需通用规划器，机器不应替模型决策 |
| 复合目标（Reach∧Break∧Place） | 混合即需定序，滑向规划器 |
| move/mine/place 三槽并行 + 静默顶替 | 抢资源无仲裁；单槽 + 显式 cancel |
| 「获取掉落」作 mine 判据 | goal 判据取世界状态，获取是模型上游决策 |

### 决策层

| 否定 | 理由 |
|---|---|
| Baritone 默认真实世界规划 | 与观察记忆哲学相反，只抄 BlockSource 抽象 |
| `hasThrowaway` 全局布尔 | 学 mineflayer 剩余垫块计数进 A* 状态 |
| `prepared()` 暴力兜底挖 | 会挖掉规划期当空气的格 |
| GOAP 状态空间搜索 | 不适合几何运动 |
| mineflayer 盲执行 | 无执行期一致性重算 |
| Voyager 让 LLM 写代码 | 不透明、不可控 |

## 7. 搁置与未决

- **搁置**：`attack` 门控（W09）；DNF 细节（REF 组合 / 预编译缓存）。
- **待确认**：对 W09「每个决定要有理由和记录」的解读（约束产品，还是也约束 AI 的每次选择），需维护者按 G02/G05 确认。
- **未决**：终局事件统一成 `GoalEvent` 还是保留 `MoveEvent`/`MineEvent`；goal 回执（job_id vs 受理）；长期记忆编辑工具（全文→定向编辑）；DNF 求值性能预算与策略 revision 快照；取消语义细节（时延 / 幂等 / 悬空落地）；原语 × goal 并发仲裁；寻路代价改造的改动地图（破拆代价走 BlockSource / mines 授权清单 / 放置动作 / 背包快照）。
