# 轮末帧段清单：已裁内容、迁移丢件与「处境」的来历

> 本文只做两件事：把维护者已经裁过的轮末帧段清单连同出处钉住；把当前实现与它的
> 差距逐项列出。**不新增产品判断**——未落实的项标注为待办或待裁，不在此处替
> `产品.md` 或维护者作决定。
>
> 追查日期 2026-08-18；代码现状对应分支 `experiment/agent-top`。

## 1. 已裁：轮末帧装什么

### 1.1 判据

来自旧线 `中期更新-08.md`（分支 `origin/experiment/rust-viewport-incremental`，
§ 开头），维护者确立、由 `standingOnBlock` 那次裁决推广而来：

> **不打开界面就能看到的才进帧。**帧 = 被动推送；主动读取（view、未来的关注/
> 历史工具）与之并存不冲突。

这条判据是**双向**的：原版 HUD 上看得见的必须进帧；需要开界面才看得见的必须留在
界面里。`standingOnBlock` 正是因为反向不成立（「视觉通道白拿」）而被整体删除。

**「界面」不含 F3**（维护者 2026-08-21 澄清；此前本文与实现都读错过）。F3 是
叠加显示，不是 GUI：可以设想一个长期开着 F3 的玩家——他照样打开物品栏、照样
移动、死了照样看得见，和任何操作都不冲突，也不占手不占屏。所以 F3 上的东西
属于「免费常驻」，与 HUD 同档。段表里 `pose`（坐标、朝向）自己就标着「F3 注册处」
且一直在帧上，这就是证据。

**判据其实是两条，不是一条**——揉成一条正是先前读错的原因：

| | 分的是什么 | 例 |
|---|---|---|
| 一、取得成本与冲突 | 免费常驻 vs 要花动作且与移动/战斗互斥 | F3 与 HUD **进**；物品栏、容器屏**不进**，模型要花轮次自己去开 |
| 二、世界可见性 | 免费也得世界真让你看见 | `world.timeOfDay` 出局的理由是「洞内不可见」，与界面成本无关 |

按上游源码核对（26.1.2 客户端 `DebugScreenEntries`，45 项注册表）：`LIGHT_LEVELS`
在册，`DebugEntryLight` 读的正是自身所在格的 sky/block 光照——`light` 段过判据。
**没有 `TIME_OF_DAY` 这一项**；唯一碰时钟的 `DAY_COUNT` 读的是
`Timeline.getPeriodCount(OVERWORLD_DAY)`，即**天数**而非一天内的时刻，主类
`DebugScreenOverlay` 也搜不到任何时钟调用。所以「timeOfDay 因为 F3 可见所以该留」
不成立，08-02 那条出局裁定站得住；倒是**天数**作为新项过了判据（未裁，见 §4）。

## 2. 当前实现与清单的差距

当前没有「轮末帧段」这一层。上述内容分散在 `render::render_situation_lines`
（称作「处境」）与增量帧两处。逐项对照：

| 已裁段 | 现状 |
|---|---|
| viewport | 在帧上 ✅（2026-08-20 起方块信息不进会话区，改由 `blocks` 工具查记忆库，见 `docs/compaction-decision.md`） |
| pose | 处境 `Position` 行 |
| status | 处境 `Vitals` 行；**盔甲值缺失**（`SelfState` 无该字段，盔甲仅存在于物品栏 5–8 号格） |
| effects | 揉在处境 `Vitals` 行内，非独立段 |
| chat | 处境 `Unread` 行（只有条数，未落实「内容 + omitted 计数」） |
| world | 处境 `Environment` 行；**且把已判出局的 timeOfDay 放了回去**（`day_period_word`） |
| hotbar | ~~缺失~~ **已补**（`b0b3502`，2026-08-21）：拆成「快捷栏」与「手持」两行，因为切换栏位与格子内容变化频率差一个量级。同时给快照加了 `Inventory.space`——菜单号 36–44 只在没开容器时才是快捷栏 |
| sound | **缺失，而且比本文原先写的更缺**。~~数据齐备~~ 是**类型齐备、数据为零**：`TickSnapshot.sounds` 两处构造都是 `Window::default()`，全仓没有任何地方 push（`capture.rs` 自己的注释就写着「声音窗：生产者未落位，先空」）。azalea 也丢：`sound` / `sound_entity` 的处理函数是空体、参数写作 `_p`。要接得自己收 `ClientboundSound` / `LevelEvent`，并给 `SoundEntry` 补 `seq`（现无，无法做游标）——与 hotbar 不是一个量级（2026-08-21 核） |
| light | **缺失**。数据也没有：`TickSnapshot` 无光照字段，需机器层新采 |
| 注册式装配 | **未建**。现为 `render_situation_lines` 里的硬编码 `Vec` |

按工作量分三档（2026-08-21 重排，原表把 sound 与盔甲值都估轻了）：

- **只差渲染**：~~hotbar~~（已补）；pose/status/chat/world 属改归属；
- **要拆的**：`world.timeOfDay` 从环境行摘掉；
- **要自己收包**（azalea 收到就扔，但 `packet-event` 已开，不必改 fork）：
  sound（`ClientboundSound` / `LevelEvent`，另需给 `SoundEntry` 补 `seq`）、
  status 的盔甲值（`ClientboundUpdateAttributes` 的 `armor`；**修饰符数学不用自己
  写**，`AttributeInstance::calculate()` 是公开的）。拾取已按这条路做完（`88bf2ff`）；
- **要改 fork**：light。azalea 的 `light_update` 是空体、区块包里的 `light_data`
  在 `azalea-world` 里一次都没出现——**它根本不存光照**。要在 fork 里新存每
  section 的天光/块光半字节数组并跟着 `LightUpdate` 更新，是改 chunk 存储的热路径。
  本文原先估的「暴露一个读取口」低了一个量级。光照仍需实盘查证——「洞里黑」
  若失真模型会当真。

## 4. 已裁与未决

### 4.1 2026-08-21 维护者裁定

1. **补快捷栏段**：选中槽位 + 快捷栏物品信息。**已做**（`b0b3502`）。
2. **拾取自成一条通道**：捡到物品无论落进主背包还是快捷栏，都报「获取了什么」，
   **不显示具体槽位**；理由是「这个涉及了服务端实体的变化」。**已做**（`88bf2ff`）——
   走 `ClientboundTakeItemEntity`，因此还白得了「是谁捡走的」，那是格位差异
   通道永远看不见的事。
3. **`light` 与盔甲值都做**，但要**区分两者的信息来源**：光照是 F3 的东西，
   盔甲值是界面（HUD）的东西。工程代价见 §2 的三档——盔甲值自己收包即可，
   光照要改 fork。
4. **容器 diff** 早有设想，排在很后面，不动。它是 `inventory_changes` 那条通道的
   正主；与拾取分开之后，「当前是 X」这个措辞才名正言顺——它本来就该是读数。
5. **僵尸轮（issue #134）不动**：原因不明，修改或增加会进一步掩盖原因。
   ⚠ 仅限**行为**；观察端是旁路，多记一笔不是动（`1df93fa` 补了轮的起止）。

### 4.2 仍未决

1. **段结构**：是否按 §1.3 与 §1.4 立回注册式装配、同时拆掉「处境」这个未授权
   命名。（4.1 第 1 条只解决了内容，没解决结构。）
2. **天数（Day N）进不进帧**：按判据过（F3 的 `DAY_COUNT` 在册），但「不知道它，
   模型会做错什么」这一问答不上来——它不改变任何决定。
3. **timeOfDay 现状无裁定支撑**：08-02 判它出局，如今它在处境的环境行里
   （`day_period_word`）。撤掉，还是补一条裁定留它。
4. **chat 段**是否按已裁的「内容 + omitted 计数」落实，还是维持现在的条数。
5. **F3 注册表里我们从没考虑过的项**（源码核对得来）：`LOOKING_AT_BLOCK_STATE` /
   `LOOKING_AT_FLUID_STATE` / `LOOKING_AT_ENTITY`（准星指着什么，含方块状态与标签）、
   `BIOME`、`LOCAL_DIFFICULTY`、`ENTITY_SPAWN_COUNTS`、`SOUND_MOOD`、`HEIGHTMAP`、`TPS`。
   **判据一旦定成「F3 免费常驻」，它们全部自动过判据**——因此需要第二条尺子：
   *过判据 ≠ 值得占 token*。`LOOKING_AT` 那组最值得单议：它免费常驻，而模型
   现在要花轮次 `scan`/`look`（实盘感知占比 59%）。
6. **投递触发**与本文相邻但不同题：现为「只有 job 进展触发投递，处境与拾取搭车」
   （`fe48330`）。触发分级属唤醒判据，见 `docs/wake-criterion-decision.md` §9，未裁。
