## 口径与范围

- 维护者把 TS 实现定为参考答案、TS 测试定为行为规范的可执行版本，并要求测试迁移逐条对应、保留断言语义，不得按理解重写（`任务书.md:5-7`）。因此下表以一个 `test(...)` / `def test_...` 为一条；“行为规范”行必须在 Rust 中保留表内列出的每一项断言语义（`任务书.md:19-22`）。
- “TS 习惯”只用于测试框架接线、Node/Mineflayer 专属对象形状或 TS 源码边界检查；这类不照抄 API 形状，但 Rust 测试必须重建相同的安全意图（`任务书.md:20-21`）。
- 自动化 TS 单元测试的权威发现规则是 `src/**/*.test.ts`（`materials/mineintent-main/package.json:11`）；Python agent 测试的发现规则是 `agent-service/test_*.py`（`materials/mineintent-main/package.json:12`）。此外，两个 Paper 实机入口由独立脚本执行（`materials/mineintent-main/package.json:13-14`），另列在“非用例式入口”中。
- 核心自动发现集共 27 个 `.test.ts` 文件、137 条 TS 用例，以及 2 个 Python 文件、25 条 agent 用例；该静态枚举绑定 TS 基线 commit `6fb3ed0c007601b4e1eb1cb0a9d10525ac2a2467`，逐文件小计和逐条锚点均在下表。Python 行全部明确标成“agent 层；本次不迁”，符合任务书边界（`任务书.md:22`）。
- 下表中的 `1.21.1` 是旧 TS oracle 的精确 fixture；已定 Rust 目标是 Paper `26.1.2` / protocol `775`（`任务书.md:5`、`任务书.md:13-14`）。机械迁移应保留“严格拒绝非目标版本、报告实际目标版本和生命周期断言”的语义，并按 SEAM-07 更新版本化 fixture，不能要求新 Rust 栈继续报告旧字面量。

## 明确的行为规范覆盖缺口

- **记忆只有“广告正确”和“不应写入”的断言，没有正向落盘用例。** 当前相关测试一处只核对 `remember` 出现在工具列表且描述不过度替模型规定记忆内容（`materials/mineintent-main/src/participant/runtime.test.ts:305-320`）；另一处只核对没有调用 remember 的闭环结束后 `memory.list('w')` 为空（`materials/mineintent-main/src/participant/runtime.test.ts:458-500`）。这两条都没有执行 `remember` capability，也不能证明文件真的落盘。
- runtime fixture 会在新临时目录中用尚不存在的 `memory.json` 启动 store，闭环用例又断言 opening `stable.memories=[]` 与 `memory.list('w')=[]`，因此现有测试**间接覆盖** missing-file load 成为空集合以及空 list/search 路径（`materials/mineintent-main/src/participant/runtime.test.ts:235-263`、`materials/mineintent-main/src/participant/runtime.test.ts:458-500`）。仍没有可机械移植的独立 oracle 覆盖 malformed/错误版本 file schema、record 校验与关键词去重、正向持久化后重载、返回 clone、非空 world 过滤/搜索排序、串行写与 `0o600` mode（实现路径：`materials/mineintent-main/src/memory/memory-store.ts:24-76`），也没有 remember 的空摘要失败、world/chat evidence 绑定、journal 不写摘要、scope 变化传播、成功/失败结果（`materials/mineintent-main/src/participant/capabilities/remember.ts:20-45`）。这些是**覆盖缺口**，不能从不存在的测试中虚构行为裁定；迁移前应补 TS characterization test，或由维护者另给 Rust 验收断言。
