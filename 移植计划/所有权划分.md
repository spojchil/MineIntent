# 所有权划分

## 结论

建议使用 **2 个移植代理并行**，但先冻结跨组契约，再按“世界/信息面”和“决策/运行面”独占文件。当前依赖在 `ParticipantRuntime` 汇合：它同时消费 Information、Memory、Execution、Minecraft、Model、Speech、Telemetry 与 capability（`materials/mineintent-main/src/participant/runtime.ts:1-42`），应用组装又在一个入口创建 backend、memory、journal、tool bridge、model、runtime 和 debug server（`materials/mineintent-main/src/app/mineintent-app.ts:19-50`）。因此并行可行，但 `participant/runtime` 和 `app` 必须只有一个所有者。

本建议不授权修改本规划任务的只读材料；它描述后续真正移植时的所有权。当前任务仍只允许写 `计划/` 与 `进度日志.md`（`任务书.md:27-34`）。

## 后续 Rust 目标树与 manifest 所有权

无论维护者最终选择单 crate 还是 workspace，目标树也使用唯一写 owner，避免只按 TS oracle 分组却让 Cargo 根文件成为共享冲突点：

| 后续 Rust 路径/文件类别 | 唯一 owner | 规则 |
|---|---|---|
| 中间层 app/runtime/model/memory/speech/telemetry crates 或 modules | B | 与上面的决策/运行面一致；目标目录名可由仓库布局决定。 |
| 中间层 information/backend-adapter/integration crates 或 modules | A | 与世界/信息面一致；backend adapter 只依赖冻结 contract。 |
| 中间层仓库根 `Cargo.toml`、`Cargo.lock`、`rust-toolchain.toml`、顶层 `src/main.rs`/`src/lib.rs`、构建与 CI 配置 | B（集成 owner） | A 通过自己 crate 的 manifest 提依赖变更；B 在独立集成提交更新 workspace members、root dependencies 与 lockfile，二者不并发编辑。 |
| 独立 backend-rs 仓库的 `Cargo.toml`、`Cargo.lock`、`src/**` | A | 只有在 SEAM/VIEW/能力差距裁定要求底层变更时编辑；B 不直接修改。backend-rs 当前 crate 根与公开模块可见于 `materials/backend-rs/Cargo.toml:1-16`、`materials/backend-rs/src/lib.rs:1-6`。 |

上述目标路径是所有权规则而非仓库布局裁定；SEAM-01/SEAM-02 未答前不创建既成 workspace 结构。

## 并行开始前必须冻结的集成件

### I01｜Backend port 与 DTO fixture（A 写、B 读）

冻结 Rust trait 对 `start/stop/state/snapshot/subscribe/observation/motor/send_chat` 的映射、错误类型、epoch/scope 字段和 fact source。TS 原接口锚点是 `materials/mineintent-main/src/minecraft/contracts.ts:11-285`，Rust 现有来源锚点是 `materials/backend-rs/src/protocol.rs:18-60`、`materials/backend-rs/src/runtime.rs:356-585`。SEAM-01–SEAM-15 中尚未裁定且会改变该 trait/wire 的部分必须标作 blocked/TODO，不由任一代理猜测。

交付给 B 的不是 A 的内部类型，而是：公共 trait、最小 DTO、固定 JSON/struct fixtures、fake backend builder，以及 ready/death/dimension/reconnect/close 的事件序列 fixture。

### I02｜Information facade（A 写、B 读）

冻结 `compose_passive_observations`、viewport 完整读、scope snapshot 与 omission/error 类型。当前 runtime 只从这一面组合 opening/post-tool frame（`materials/mineintent-main/src/participant/runtime.ts:376-381`、`materials/mineintent-main/src/participant/runtime.ts:525-549`），provider 内部的 catalog/ref/cursor 不应泄漏给 B。

交付给 B：四类 provider 的 plain values fixture、denied/unavailable/partial/timeout fixture、viewport DTO fixture。

### I03｜Agent/capability contracts（B 写、A 读）

B 冻结 `AgentFrame`、tool definition/invocation/result 与 capability execution context。当前 agent-context 与 invocation schema 在 `materials/mineintent-main/src/models/contracts.ts:1-62`、`materials/mineintent-main/src/models/contracts.ts:79-101`，工具响应信封在 `materials/mineintent-main/src/models/tool-bridge.ts:7-10`、`materials/mineintent-main/src/models/tool-bridge.ts:45-63`。

A 的 Information/Paper 测试只消费 frame/viewport fixture，不修改这些类型。若 backend 新字段需要模型可见，先在 SEAM-06/SEAM-07 形成明确决定，再由 B 改 contract、A 同步 adapter。

### I04｜总装构造面（B 集成，A 提供 factory）

A 提供 `BackendPort` 与 `InformationFacade` 的构造函数/factory；B 在 app/runtime 层完成唯一总装。当前唯一汇合点分别是 `buildInformationRuntime()`（`materials/mineintent-main/src/participant/runtime.ts:577-592`）与 `MineIntentApp.start()`（`materials/mineintent-main/src/app/mineintent-app.ts:19-50`）。代理 A 不编辑 app/runtime，代理 B 不越过 factory 访问 backend 内部。

## 提交与集成顺序

1. **契约冻结提交**：A 提交 I01/I02，B 提交 I03；双方只评审、不交叉改文件。需要维护者答案的字段保持显式未决。
2. **并行叶子提交**：A 从 geometry/contracts/stores/provider/backend adapter 开始；B 从 DTO/contracts、journal、arbiter、speech scheduler、transport validation 开始。依赖顺序以 `计划/模块清单.md` 为准。
3. **组内组合提交**：A 完成 information runtime 与 Paper/backend fixture；B 完成 capabilities、Agent Service bridge、memory 已裁定部分。
4. **单点集成提交**：B 只在 `participant/runtime` 与 `app` 接入 A 的 factory；A 通过 fixture/trait 修正自己一侧，不直接修改集成文件。
5. **oracle 验收提交**：每条 TS 测试由生产文件 owner 迁移；跨组场景由 A 写 backend/world fixture、B 写 runtime 期望，最终断言文件归其生产入口所有者。

## 防冲突规则

- 任一路径永远只有上表中的一个写 owner；barrel/module exports 随所属目录归同一 owner。
- 公共 contract 变更必须先单独提交 fixture 和兼容影响，再改调用方；不能在一个代理的功能提交里顺手改另一组接口。
- `待决问题.md` 中任何会改变当前模块 contract、wire、持久格式或进程拓扑的条目未决时，使用 feature gate/trait stub 或明确 blocked test，不以临时实现制造既成事实；至少包括 DELTA-01–DELTA-04、SEAM-01–SEAM-15、VIEW-01–VIEW-02、AGENT-01–AGENT-04 与 MIG-01–MIG-04。
- 测试的 owner 跟随被测生产路径；只因 Rust mock 写法不同而调整测试夹具时，仍须保留 `计划/测试归类表.md` 标出的行为断言语义。
