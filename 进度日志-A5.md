# A5 进度日志

## 改动清单

- `crates/contracts/src/minecraft/event.rs`：收口严格 backend-event v2 envelope、九个产品 kind 与唯一 `overflow` marker；default 与 typed envelope 统一执行 protocol/kind/payload 一致性和 `deny_unknown_fields`。`player_list_add/remove/update` 使用显式 wire rename；world 的 `dimension`/`gameMode` 缺失时省略；block `Updated` 的 `oldBlock`/`newBlock` 必须出现但可为显式 null；chat 仅保留合同字段。
- `crates/contracts/src/minecraft/fixtures.rs`、`crates/contracts/tests/i01_minecraft_contract.rs`：补齐 v2 fixture、12 个 lifecycle payload 的精确 round-trip、default/typed mismatched-kind/unknown-field 拒绝、unit lifecycle 未知字段拒绝、required-nullable block、optional omission、overflow typed envelope 和 v1 mutation 证据。
- `crates/backend/src/protocol.rs`：直接 re-export contracts typed v2 事件合同；命令输入保持严格 command wire。
- `crates/backend/src/runtime.rs`：生产 writer、生命周期、server chat、typed observation adapter 和 global drainer 直接使用 v2；keep-alive 只留协议本地，motor completion 走最小 typed future，commanded/initial chat 不进 global stream。
- runtime 增加 active Move 独立 cancel signal、generation/ownership 清理、物理 release 后 completion settle，以及 stop/disconnect 对 queued/active command 的结算；登记态覆盖首个 actuator 前窗口，stop 后不会复活动作。
- runtime 的 enqueue、stop、reconnect attempt/add intent、Respawn actuator 和晚到 Init/Login/Spawn/Tick/Chat 等路径共享 admission 纪律；重连 add 可被 stop 的 Notify/Token 取消，终态不会被后续 attempt 重置。
- 管理侧终审又封住首次 disconnect cleanup 与并发 stop 的窄窗口：首次 close 在同一 admission 临界区内先取消 active/queued command、清空 observation，再允许 `connection_closed`/`stopped` 排水；duplicate disconnect 保留幂等清理。具名回归 `stop_cannot_overtake_first_disconnect_cleanup` 用阻塞 cleanup seam 证明 stop 不能越过该边界。
- `.codex-progress.jsonl` 持续记录里程碑；本工作树未提交 commit。

## 合同与生命周期映射

- lifecycle 仅发出 `connection_requested`、`transport_connected`、`logged_in`、`ready`、`died`、`respawn_transition_started`、`respawned`、`dimension_changed`、`reconnect_scheduled`、`connection_closed`、`faulted`、`stopped`。
- `server_shutdown`（含空格写法）/`server restarting`/`server closed` 归类为 retryable `server_shutdown`；其余带 reason 的 kick 不从文本猜测 timeout/unsupported，而是 fatal `unclassified_kick`。reconnect schedule 复用同一个 sealed close code。PermissionDenied 等真实 fatal failure 优先于 `reconnect_disabled`。ConnectionFailed 的 error 保存在 `BackendClose.error`。
- expected stop 顺序固定为 close、资源/活动 Move release 与 completion settle、stopped(reason)、shutdown；每个 attempt 只由 disconnect seal 一个 close。

## 主审追加收口

- `finalize_stop_if_ready` 改为 readiness 检查、reason take、`stopped` 入队共享
  `command_admission`，新增双 finalizer barrier 回归，消除 reason 丢失唤醒。
- 正常产品/协议事件通过 admission 内直接入队、解锁后排水；晚到 Init/Login/Spawn/Death、
  chat/player-list/chunk/tick/snapshot、respawn 与重连 fault/schedule/add 均不能越过
  `stopped`。Death 的同步 claim、物理 release、active/generation 清理和 completion settle
  在 `died` 可见前完成；重入 stop 不会再触碰 bot。Move 首 actuator 也在同一代 admission
  内检查 cancellation。

  `server_shutdown` 下划线/空格、server closed/restarting；kick 文本的
  unsupported/version/timed out 不再伪造 forced/timeout code，普通 reason 一律
  `unclassified_kick` fatal；invalid session/authentication/not authenticated 保留
  `permission_denied` close 与 authentication/permission failure 细分。
- 新增并逐条以 `--exact --nocapture --test-threads=1`（每条 120s 工具上限）运行的具名
  测试全部通过；管理侧终审追加 disconnect-cleanup 回归后 backend lib 为 86 passed，contracts i01 为 30 passed。曾出现的旧
  测试孙进程已由管理端进程树清理，复核无残留。
